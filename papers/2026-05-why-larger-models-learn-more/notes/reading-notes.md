## 核心问题

为什么更大的模型会学到更小模型学不到的任务？这种差异是否只是因为大模型样本效率更高，还是因为小模型在同一数据混合和优化机制下存在更根本的学习瓶颈？

## 论文明确说的内容

作者的主张是：大模型的优势可以由数据混合引发的资源竞争解释。小模型会把有限神经元优先分配给高频任务或低复杂度任务，因此即使它具备表达某个稀有任务解的能力，也可能无法在混合训练中稳定学到这个任务。

论文区分了两种情况：

- `learnable via data scaling`：小模型只是欠训练，给更多数据后可以达到大模型有限资源训练下的损失。
- `learnable via model scaling`：即使给小模型无限数据，它也无法达到大模型有限资源训练下的损失，因此必须增加模型规模。

在合成多任务回归设置中，任务特征是否被保留取决于 utility：

```text
u_{k,j} = pi_k * lambda_{k,j}
```

其中 `pi_k` 是任务频率，`lambda_{k,j}` 是该任务第 `j` 个特征方向的重要性。宽度为 `N` 的模型保留 utility 最大的 `N` 个特征。因此，低频任务和谱衰减较慢的复杂任务更容易被小模型遗漏。

论文进一步把这个现象解释为梯度干扰：**稀有任务出现时会写入一些特征信号，但频繁任务在间隔期间的更新会覆盖这些信号。大模型因为有更多参数可容纳频繁任务，频繁任务残差更小、梯度更弱，所以更不容易覆盖稀有任务特征。**

## 推断 / 个人理解

这篇论文对 pretraining 数据配比的启发是：稀有任务不是简单“多采样一点就够”，因为采样频率、任务复杂度和模型容量一起决定了它的特征是否能被保留下来。对小模型来说，提高稀有任务采样权重可能有帮助，但如果容量仍被高 utility 特征占满，仍可能出现学到后被覆盖的问题。

这也给“为什么后训练可以教会小模型某些能力”一个解释：单独 post-training 时，数据混合更集中，干扰源减少，小模型表达能力够用；但在预训练混合分布中，同一能力未必能自然出现。

## 如何获得任务频率和复杂度谱

在论文的合成回归实验中，`pi_k` 和 `lambda_{k,j}` 都是实验者设定或可直接计算的量：

- `pi_k` 是任务 `k` 在训练 mixture 中的采样概率。论文里常用 power-law prior，例如 `pi_k ∝ k^{-beta}`，再归一化到所有任务概率和为 1。
- `lambda_{k,j}` 是任务 `k` 的谱，即任务协方差矩阵 `C_k = B_k Lambda_k B_k^T` 的第 `j` 个特征值。论文里常用 `lambda_{k,j} ∝ j^{-alpha_k}` 来控制任务复杂度。

因此在 toy setting 里，判定一个特征是否会被学到，就是把所有任务特征的 `pi_k * lambda_{k,j}` 排序，看模型宽度 `N` 能保留 top-N 中哪些特征。

在真实 LLM 预训练中，这两个量没有直接观测形式，只能操作化估计：

- `pi_k`：先定义任务检测器或任务标签，再统计训练语料中任务样本占比。论文第 4 节为了避免自然任务频率难测，采用人工注入任务来控制频率；对于参考任务，则用字符串模式或类似 infini-gram 的工具估计出现频率下界。
- `lambda_{k,j}`：真实任务没有显式线性协方差谱。可替代估计包括：任务表示的 PCA / feature spectrum、线性 probe 所需维度、任务 loss 随模型宽度下降的曲线、达到固定准确率所需的有效特征数，或任务机制本身需要多少独立子能力。

所以，把公式用于真实任务时要谨慎：`pi_k` 可以相对直接地由采样或检索统计得到；`lambda_{k,j}` 更像任务复杂度的局部线性近似，而不是客观唯一的任务属性。

## 数学步骤级批改任务中的判定方法

问题：如果目标任务是数学解答题学生作答批改的步骤级合成数据，包含题目分析、思路分析、学生作答分步骤验算、分数划分等，如何知道哪些能力或特征是 `learnable via data scaling`，哪些是 `learnable via model scaling`？

### 任务拆解

不要试图直接求真实任务里的 `lambda_{k,j}`。更实用的做法是先把“步骤级数学批改”拆成可测能力，再做小模型、大模型、更多数据之间的对照实验。

可拆分的子能力包括：

- 题目理解：识别题型、条件、目标量。
- 解法规划：判断应使用代数、几何、函数、概率等哪类方法。
- 标准解生成：模型自己是否能先解出正确答案。
- 学生步骤解析：把学生作答拆成步骤和中间结论。
- 局部验算：判断某一步推导是否成立。
- 错误定位：找到第一次错误或关键错误。
- 错误类型归因：计算错、公式错、逻辑跳步、条件误用、单位 / 定义错误等。
- 分数划分：按 rubric 给步骤分。
- 反馈生成：给出可读解释，而不是只判对错。
- 多错误交互：学生前一步错了，后面基于错误结果继续推导时如何给分。

这些子能力可以视为真实任务里的 task / feature 候选。

### 评测集设计

每个子能力都应建立独立 eval set。例如对“学生分步骤验算”，可覆盖：

- 单步算术错误。
- 单步代数变形错误。
- 正确但跳步。
- 前提错误导致后续全错。
- 中间结果错但方法正确。
- 最终答案对但过程有漏洞。
- 多个错误叠加。
- 非标准解法但正确。
- 学生文字表达含糊。
- rubric 需要部分给分。

指标可以包括 accuracy、F1、score error、first-error localization accuracy、rubric agreement 等。

### 判定实验

对每个能力 `k`，至少比较三组：

```text
Small model + 少量该能力数据
Small model + 更多该能力数据
Large model + 少量 / 正常该能力数据
```

如果小模型随着该类数据增加持续提升，并能接近大模型表现，则更像：

```text
learnable via data scaling
```

如果小模型增加很多同类数据后仍明显平台化，和大模型保持稳定差距，则更像：

```text
learnable via model scaling
```

如果小模型单独训练某类数据能学会，但放进完整 mixture 后学不会或不稳定，则说明该能力可能是 interference-sensitive，接近论文讨论的数据混合干扰机制。

### 可能的 data scaling 能力

以下能力通常更可能通过增加数据解决：

- 简单计算错误识别。
- 明确公式套错。
- 单步代数等价判断。
- 按固定 rubric 给分。
- 常见题型的标准错因分类。
- 高频、局部、模板化、低歧义的批改场景。

例如，学生把 `2x + 3 = 7` 算成 `x = 5`，这是高频、局部、低复杂度错误，通常更可能是 data scaling 可学。

### 可能的 model scaling 能力

以下能力更可能需要模型规模，或至少需要改训练机制来降低干扰：

- 非标准解法的正确性判断。
- 多步依赖下的 first error 定位。
- 学生前面错了，但后续逻辑在错误前提下是否一致。
- 复杂证明题的局部逻辑有效性判断。
- 需要先完整解题再反向批改的任务。
- 多个评分规则冲突时的 rubric arbitration。
- 文字表达含糊但数学意图可恢复的情况。
- 低频、多步、非模板、高歧义、需要全局一致性的批改场景。

例如，学生第 2 步用了一个隐含单调性结论，第 4 步结果正确，但第 2 步只在额外条件下成立；评分时应扣逻辑严谨性分但不扣计算分。这类样本低频、多步，并且需要题目条件和学生过程联合建模，更像 model scaling 候选。

### Capability matrix

实践上可以建立一个 capability matrix：

```text
能力 × 题型 × 学生错误类型 × 步骤长度 × rubric复杂度
```

每个格子记录：

```text
small_1x_data_score
small_4x_data_score
small_16x_data_score
large_1x_data_score
large_4x_data_score
```

建议标签规则：

```text
data_scaling:
  small_16x 接近 large_1x

model_scaling:
  small_16x 仍显著低于 large_1x

interference_sensitive:
  单独训练能学会，混合训练学不会或退化
```

这类实验的价值不是笼统判断“数学批改是否需要大模型”，而是找出哪些子能力可以靠合成数据补齐，哪些子能力需要更大模型，哪些子能力主要是数据 mixture 中被高频简单任务覆盖。
